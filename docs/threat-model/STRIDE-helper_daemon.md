# STRIDE Threat Model - Privileged Helper Daemons (discoverd, captured, scand, interceptd)

| Threat Category | Description | Specific Impact on NetSentinel | Mitigation |
|---|---|---|---|
| **Spoofing** | Rogue process impersonating a daemon on D-Bus system bus. | Unauthorized execution of privileged operations (scan, capture, ARP spoof). | D-Bus policy files restrict `org.netsentinel.*` bus names to specific user/group. Polkit gates every method call with caller UID validation. |
| **Tampering** | Modifying a daemon binary on disk to inject malicious logic. | Arbitrary code execution with `cap_net_raw` or root privileges. | `.deb` package signed GPG; integrity verified at install. Binaries in root-owned paths (`/usr/libexec/`). `postinst` applies `setcap` only to known binaries. File integrity monitoring via AIDE or similar. |
| **Repudiation** | Operator denies initiating a scan or intercept session. | Legal liability for network disruption or unauthorized interception. | Every daemon method call logs to the cryptographically chained audit ledger (`netsentinel-core::ledger`) before and after execution. HMAC-SHA256 signed JSONL in `/var/log/netsentinel_audit.jsonl` for intercept daemon. |
| **Information Disclosure** | Daemon process memory leaks captured packets, ARP data, or scan findings to other local users. | Sensitive network topology or credentials exposed. | Each daemon runs under a dedicated system user (`netsentinel-helper`), not root. Process memory is not shared between daemons. D-Bus access restricted to `netsentinel` group via AppArmor profiles. No core dumps in production (`ulimit -c 0` in systemd unit). |
| **Denial of Service** | A malicious D-Bus client floods a daemon with requests, exhausting resources. | Daemon becomes unresponsive; legitimate UI operations fail. | Rate limiting on D-Bus method calls (configurable per daemon). systemd `MemoryMax=`, `CPUQuota=`, `TasksMax=` limits on service units. Scan daemon enforces `--max-rate` on nmap. Intercept daemon has hard 30-minute session timeout. |
| **Elevation of Privilege** | Exploiting a vulnerability in a daemon (e.g. ARP parsing in discoverd, eBPF verifier bypass in captured) to gain root. | Full system compromise. | Daemons use minimal capabilities (`cap_net_raw` only), not full root. AppArmor mandatory access control profiles restrict filesystem/network access. eBPF program passes kernel verifier. No `unsafe` code outside of `pnet` raw socket and `aya` eBPF interfaces. Pulse and packet parsing are bounds-checked. |
