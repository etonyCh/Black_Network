# STRIDE Threat Model - D-Bus Inter-Process Communication

| Threat Category | Description | Specific Impact on NetSentinel | Mitigation |
|---|---|---|---|
| **Spoofing** | Unauthorized process connects to D-Bus system bus and calls `org.netsentinel.*` methods. | Arbitrary privileged operations executed (scan, intercept, capture) without authorization. | D-Bus policy files (`packaging/dbus-system.d/`) restrict bus name ownership and method access to the `netsentinel` system user. Polkit authentication required for every privileged method call. UI daemon connects as unprivileged user. |
| **Tampering** | Man-in-the-middle on D-Bus messages between UI and daemons (theoretical on local system bus). | Modifying scan targets, intercept parameters, or consent tokens in transit. | D-Bus system bus is kernel-mediated (not network-exposed). Messages are not encrypted in transit but are protected by kernel-mediated delivery. Integrity relies on OS-level D-Bus daemon (dbus-daemon) not being compromised. For high-security environments, D-Bus mandatory access control via SELinux/AppArmor enforces message routing. |
| **Repudiation** | UI sends a command, daemon executes it, but UI denies having sent it. | Dispute over who initiated a scan or intercept. | Every D-Bus method call that results in a privileged action is logged by the daemon to the audit ledger with the caller's UID (obtained via `zbus::Message::sender()`). Consent hash (RE-01) is included in the D-Bus call context. |
| **Information Disclosure** | Eavesdropping on D-Bus system bus messages to discover scan targets, captured packets, or credentials. | Attackers learn network topology, vulnerabilities, or intercepted data. | D-Bus policy files restrict which users can `eavesdrop` on `org.netsentinel.*` signals. Only the `netsentinel` group user can subscribe to signal streams. Sensitive data (credentials, raw packets) is never sent over D-Bus — only metadata and references. Raw capture data stays in eBPF perf buffer → daemon memory. |
| **Denial of Service** | Flooding the D-Bus system bus with messages to `org.netsentinel.*`, preventing legitimate UI-daemon communication. | Application becomes unresponsive; all views show connection errors. | D-Bus rate limiting at the daemon level (reject calls if >N per second from same sender). systemd watchdog (`WatchdogSec=`) ensures daemons restart if hung. UI shows user-friendly error with retry option on D-Bus timeout. |
| **Elevation of Privilege** | Exploiting a D-Bus method's input validation to inject parameters that escalate beyond intended capability. | E.g., passing a malicious interface name to `start_capture()` that triggers command injection. | All D-Bus method inputs are validated with strict schemas (IP format, interface name whitelist, token format) before execution. Interface names validated against `/sys/class/net/` existence. No string interpolation into shell commands — all `subprocess` calls use `argv[]` arrays. Pydantic-style validation equivalent in Rust (pattern matching + regex). |
